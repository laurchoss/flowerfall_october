# flowerfall_october

Первая версия учёта продаж цветочного бизнеса за **октябрь 2026**.
Python 3.10+, macOS или Linux, только стандартная библиотека — установка пакетов не требуется.

## Быстрый запуск

```sh
python3 flowerfall.py init
python3 flowerfall.py sale '20.10 букет Осень 1шт итого 3500 сайт'
python3 flowerfall.py report --input examples/daily_report_demo.txt
python3 flowerfall.py summary
```

Команды создают локальную папку `data/`. Откройте CSV в Excel, Numbers или LibreOffice: UTF-8 с BOM, разделитель `;`.

- `sales_october_2026.csv`: дата, букет, количество, цена, сумма, канал, примечание.
- `daily_reports_october_2026.csv`: разобранные дневные отчёты.
- `daily_reports_october_2026.json`: архив исходных сообщений и результатов проверки.
- `finance_october_2026.csv`: таблица за все 31 день, 11 колонок: число, имя, зарплата, выручка, наличка, Б/Н, перевод, остаток кассы, списание, закупка, прочие расходы.

Другую папку можно задать **перед** командой: `python3 flowerfall.py --directory demo-output init`.
Пример отчёта содержит вымышленные данные.

## Правила учёта

Продажа: `20.10 розы 3шт 1500 WhatsApp` означает 3 × 1500 ₽.
Слово `итого` задаёт сумму всего заказа. Каналы: WhatsApp, сайт, офлайн.
Примечание добавляется после `;`. При ошибке пакет продаж целиком отклоняется.
Повторный ручной ввод продажи добавляет новую строку; защита от повторной доставки действует в Telegram.

Дневной отчёт начинается с даты и содержит суммы с названиями полей — см. пример.
QR включается в Б/Н. Выручка сверяется с суммой оплат; расхождения сохраняются в архиве и попадают в `ожидают_уточнения`, но не включаются в сводку. Команда возвращает код 1, если есть такие отчёты.
Пустые значения остаются пустыми. Нулевые суммы нужно указывать явно.
Повтор одинакового дневного отчёта не удваивает выручку; другой отчёт за уже занятую дату отклоняется.

Дневные итоги и отдельные продажи учитываются раздельно — их нельзя складывать, иначе выручка удвоится.
Рабочие CSV, архивы и база SQLite исключены из Git. Делайте их резервные копии отдельно.

## Telegram (необязательно)

```sh
cp bot_config.example.json bot_config.json
# Вставьте свой токен BotFather в bot_config.json
python3 telegram_bot.py --check
python3 telegram_bot.py
```

Проверка покажет имя бота и личную команду подключения `/start …`.
Код подключения храните как секрет. Первый подключившийся личный чат становится владельцем; группы и другие пользователи не получают доступ.
Бот работает, пока процесс запущен и есть интернет. На macOS доступен `python3 bot_control.py start|status|stop`.
Данные бота сохраняются в корне проекта, отдельно от папки CLI `data/`.

В боте есть пошаговый «Отчёт за день», предварительный просмотр, подтверждение, отмена и сохранение черновика после перезапуска.
Пробный режим сохраняет отчёты отдельно; исправления через кнопки доступны только в пробном режиме. Месячные итоги в Telegram отключены. В рабочем режиме исправление дневного отчёта требует ручной сверки архива; автоматического исправления через бота пока нет.

## Google Sheets (необязательно)

По умолчанию отключено. Для интеграции используется `google_sheets_bridge.gs`:
в свойствах Apps Script задайте `SPREADSHEET_ID`, `TAB_NAME`, `SYNC_SECRET`, разверните Web App и укажите URL и тот же секрет в локальном `bot_config.json`.
Лист должен содержать 11 заголовков из `daily_reports.BUSINESS_HEADERS` и по одной строке на дату `01/10` … `31/10`.
Скрипт отказывается перезаписывать отличающиеся суммы и формулы. Без настройки этой интеграции локальный сбор работает самостоятельно.

## Проверка

```sh
python3 -m unittest -v
```

Тесты используют временные папки и не обращаются к Telegram/Google.
GitHub Actions проверяет Python 3.10, 3.12 и 3.13.
В публичном репозитории находятся код, тесты и демонстрационные данные; токены, реальные отчёты, личная Google-таблица и настройки компьютера не публикуются.
